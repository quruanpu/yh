# BI Skill 方法路由重构计划

## 目标

让 BI 查询 AI 助手按“当前上下文优先、方法按需加载、工具只读取证”的方式工作。尤其是同环比/时间对比，不再固定绑定主查询，而是根据当前打开的 BI 查询面板、指标详解弹窗或主查询页面选择对应方法分支。

## 原则

- 不修改页面布局、样式、按钮、弹窗和工具执行协议。
- 不新增业务 UI，不改变查询工具返回结构。
- skill 主文档保持轻量，只放读取顺序和路由原则。
- 详细分析方法放入 `methods`，业务场景仍放入 `scenarios`。
- 当前打开面板是默认分析上下文；其它工具只作为用户意图或证据不足时的辅助。

## 设计

1. 文档结构
   - `SKILL.md`：入口规则和读取顺序。
   - `manifest.md`：统一登记场景和方法。
   - `references`：工具协议、字段、回答和运行时通用编排。
   - `scenarios`：客户、商品、模板、目标、趋势等业务场景。
   - `methods/同环比分析`：时间对比方法索引与主查询、BI 查询、指标详解三条分支。

2. 运行时路由
   - `gz.js` 在快照中增加 `activeContext`。
   - `skill.js` 解析 `scenarios` 和 `methods`。
   - 命中同环比/时间对比时，先加载方法索引，再按 `activeContext` 和用户意图加载分支。

3. 工具选择
   - 指标详解弹窗打开时，默认使用指标详解工具做时间对比。
   - BI 查询面板打开时，默认使用 BI 查询面板工具做时间对比。
   - 无弹窗或用户明确问客户/商品/明细/贡献结构时，使用主查询。
   - 跨工具结果只能辅助解释，不能混算。

## 验证

- `node --check` 验证运行时代码语法。
- 扫描旧的“同环比优先主查询”提示是否残留。
- 扫描删除后的旧同环比场景路径是否仍被引用。
- 确认改动不涉及 CSS、HTML 结构和 UI 渲染文件。
