# 登录统一接入改造计划

## 总体路线

按“先定边界，再收入口，再迁移业务，再清理残留，再验收”的顺序执行。

每完成一个阶段，都做一次语法检查和调用链检查。

## 阶段 0. 基线审查

目标：

- 盘点所有登录入口
- 盘点所有凭证读取点
- 盘点所有 BI 代理和 token 校验点
- 盘点所有直接读 `localStorage` 的地方

产物：

- 当前调用清单
- 待迁移文件清单
- 风险点清单

验收：

- 能明确区分“登录模块内部逻辑”和“业务模块绕行逻辑”

## 阶段 1. 入口收口

目标：

- `index.html` 只保留一个登录入口脚本
- 登录模块内部动态加载子模块
- 登录模块最先初始化

执行：

1. 调整 HTML 脚本顺序。
2. 去掉 HTML 中登录子模块的直接引用。
3. 在登录模块内部加入动态加载器。
4. 保证业务模块只在登录模块就绪后运行。

验收：

- 外部 HTML 看不到登录子模块直接引入
- 页面首个可用登录入口仍然存在
- 业务模块不受布局影响

## 阶段 2. 对外接口收口

目标：

- 只保留统一的凭证获取接口
- 删除旧接口壳和重复入口

执行：

1. 新增统一凭证获取方法。
2. 统一成功返回结构。
3. 统一失败返回结构。
4. 删除旧的薄封装接口。

验收：

- 调用方只认一套返回格式
- 没有第二条登录分支

## 阶段 3. 登录内部子模块重构

目标：

- 登录子模块只做各自系统的认证动作
- 统一由登录模块编排恢复、验证、回写

执行：

1. SCM 子模块只处理 SCM 验证。
2. PMS 子模块只处理 PMS 验证。
3. BI 子模块只处理 BI 代理与 token 验证。
4. `auth/app.js` 负责统一恢复排序。

验收：

- 各子模块不再对外暴露多余入口
- 登录顺序可被统一控制

## 阶段 4. 业务模块迁移

目标：

- 所有业务模块都通过登录模块拿凭证
- 不再直接读登录缓存

优先顺序：

1. 商品查询
2. 优惠券
3. 工具中心
4. 智聊工具接口
5. BI 运营模块

验收：

- 搜索不到新的业务侧 `localStorage.getItem('xxx_login')`
- 搜索不到新的业务侧 token 校验

## 阶段 5. 残留清理

目标：

- 删除死代码
- 删除重复中间层
- 删除多余兼容逻辑

执行：

1. 去掉无用方法。
2. 去掉无用变量。
3. 去掉绕行调用。
4. 去掉重复 fallback。

验收：

- 只保留最短可读链路

## 阶段 6. 验证和上线

目标：

- 全量语法检查
- 调用链检查
- 关键业务回归检查
- 部署到 GitHub

验收：

- 无语法错误
- 无乱码造成的断链
- 无新增布局变化
- 无重复登录逻辑
