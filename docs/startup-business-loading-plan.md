# 业务模块加载链优化计划

## 目标

- 修复 BI 汇总查询、目标模板下载/上传对 `XLSX` 的隐式全局依赖，保持 Excel 库按需加载，不回退到首屏加载。
- 避免用户点击优惠券、商品查询、BI 运营查询、工具中心时右侧主内容区出现空白。
- 保持所有业务行为、功能、布局样式不变；只调整加载时机、依赖入口和切换时序。
- 保留登录与数据库后台副作用的正确触发：登录、设备、Firebase、SCM/PMS/BI 凭证校验优先；优惠券后台共享清理与赠券监听仍在 SCM 认证后自动运行。

## 当前判断

- `index.html` 只加载系统壳、通知、轻量配置/工具、登录和智聊 loader。
- `script.js` 注册优惠券、商品查询、BI 运营查询、工具中心为懒加载模块。
- 智聊已经有轻量壳，默认首屏不会空白。
- 四个业务模块点击后存在空白窗口：主框架先隐藏当前模块，再等待目标模块脚本、子模块、实例全部就绪。
- `XLSX` 从首屏移走后，BI 导出链没有按需加载 Excel 库，会在直接进入 BI 导出时失败。

## 设计原则

1. 不做通用加载页覆盖业务页面。
2. 模块点击时应尽快出现该模块自己的原生页面结构。
3. 可以后台执行模块脚本来创建隐藏 DOM，但不能调用 `show()` 阶段业务动作。
4. 业务模块应在启动期并发初始化，模块内部仍保持自身脚本依赖顺序。
5. BI 大链路仍保留必要串行依赖，后续只在模块内部拆 UI 基础链和 AI/趋势扩展链。
6. 第三方库由系统级依赖加载器统一管理，本地运行时资源优先，CDN 只作为兜底。

## 分层方案

### L0 首屏系统壳

- 全局 CSS、通知、登录、轻量配置、智聊 loader。
- 不加载完整业务页面核心。

### L1 登录与数据库

- `LoginModule.init()` 保持优先。
- `scmAuthenticated` 后继续启动 `YhquanBackgroundRuntime`。
- 不因业务 UI 懒加载影响共享节点清理、自助赠券监听。

### L2 智聊首屏

- 保持当前智聊壳优先可见。
- SCM 认证后加载智聊核心。

### L3 业务模块启动期初始化

- 智聊壳开始显示后，优惠券、商品查询、BI 运营查询、工具中心并发执行模块初始化。
- 初始化只让模块完成脚本加载、`init()` 和隐藏 DOM 创建，不调用 `show()`。
- 每个模块内部仍保留原有脚本顺序，例如 BI 的 mixin/规则脚本必须先于 `app.js`。
- 用户点击已初始化模块时直接显示原生页面。
- 用户点击尚未初始化完成模块时，保持当前页面不隐藏，目标模块就绪后再切换，避免空白。

### L4 按需外部依赖

- `buju/wb/xlsx/xlsx.full.min.js` 作为本地运行时 Excel 库。
- `AppFramework.ensureExternalDependency('xlsx')` 统一加载。
- BI 导出、目标模板下载、目标模板上传读取、智聊 Excel 解析共用该入口。

## 风险控制

- 不改变业务模块 DOM 结构和 CSS 类名。
- 不改变业务查询、上传、导出、登录和数据库路径。
- 主框架切换加序号守卫，慢模块加载完成后不能覆盖用户后续选择。
- 启动期业务初始化失败只记录错误，不阻断当前首屏与智聊。
- 所有改动文件执行语法检查；关键路径做静态引用扫描。
