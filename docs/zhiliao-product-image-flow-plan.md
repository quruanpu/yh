# 智聊商品图生图链路重构计划

## 目标

让智聊在以下意图中形成稳定、自然的工具链路：

- 仅查询商品：使用 `search_product`。
- 查询商品并生成宣传图、海报、主图：先查询商品，再用商品图作为参考图调用 `generate_or_edit_image`。
- 直接生成图片：无商品或参考图依赖时直接生成。
- 用户上传参考图后生成或编辑：优先使用上传图或最近图片引用。

## 原则

- 不改消息卡片、商品卡片、生图卡片的布局和样式。
- 不用硬规则替代 AI 意图判断，不把“海报”等词强行绑定到商品查询。
- 底层只做资源上下文和参数完整性校验；能确认商品图时补齐引用，不能确认时返回结构化错误。
- 商品图片进入统一图片引用池，后续统一使用 `image_ref`，不依赖历史消息里的原始 URL。
- 前端请求保持统一格式；后端 provider 子模块负责供应商协议和返回归一。
- 前端只接收统一输出字段：`image_url`、`image_urls`、`images`，不再深度猜测供应商原始结构。

## 改造点

1. `zhiliao/gongju/jiekou/a_skill/app.js`
   - 统一商品关键词候选抽取与清洗。
   - 强化组合意图路由说明：查询商品并生成图片时先查询商品，再生成。

2. `zhiliao/gongju/jiekou/a_skill/spcx.js`
   - 使用统一关键词抽取。
   - 保持发券信号优先级不变。

3. `zhiliao/gongju/jiekou/chaxun/app.js`
   - 商品查询成功后，将可用商品图登记到会话图片池。
   - 返回 `image_ref`、`image_refs`、`first_card_image_ref`，供后续工具使用。

4. `zhiliao/zjg/yewu/yasuo.js`
   - 商品工具历史保留图片引用，不保留原始 URL。

5. `zhiliao/gongju/jiekou/a_skill/tpsc.js`
   - 生图前优先使用商品查询返回的 `image_ref`。
   - fallback 查询商品时使用统一关键词候选。
   - fallback 只在高置信度商品图生图意图且缺资源时尝试补图。

6. `zhiliao/gongju/jiekou/shengtu/http.js`
   - 保留 HTTP 请求、错误解析和网关 `body` 解包能力。
   - 移除前端对供应商原始响应的递归猜测式图片解析。
   - 只读取统一网关输出字段。

7. `大模型统一请求/src/providers/*/image`
   - 各 provider 子模块负责把供应商结果归一为统一图片输出。
   - 成功响应必须包含图片结果，否则直接返回失败。

## 验证场景

- “查询999感冒灵”
- “查询999感冒灵，并生成宣传海报！特价13.5。”
- “用刚才查到的商品生成宣传海报”
- “生成一张赛博风城市海报”
- “基于我上传的图片改成促销海报”
