# BI 通用 AI 助手架构与改造计划

## 目标

BI 查询模块只保留一个通用 AI 助手入口。

用户进入 BI 查询页面后，右下角显示唯一 AI 图标。AI 面板复用原指标详解助手的聊天布局、输入规则、流式回复和工具查询状态，但不再分别挂在 BI 查询弹窗或指标详解弹窗内部。

## 权限模型

通用助手按当前页面状态动态叠加权限。

第一，默认拥有主查询页面权限。可读取主查询当前页快照，并通过只读工具按分页、筛选、字段、聚合字段、模板 key 或模板名称查询数据。

第二，默认拥有 BI 查询面板动态查询权限。可读取当前 BI 查询面板快照，并通过只读工具传入模板、筛选、排除模式、日期字段、日期范围、聚合字段、目标范围和合并子项参数，结果仍由 BI 查询面板业务壳计算。

第三，默认拥有指标详解动态查询权限。可读取当前指标详解快照，并通过只读工具传入模板、筛选、排除模式、日期字段、日期范围、指标字段和目标范围参数，结果仍由指标详解业务壳计算。未传模板、指标或目标时，才沿用当前已打开指标详解面板口径。

## 加载策略

`index.html` 不直接追加 AI 子脚本。

`YejiModule.loadAiCoreModules()` 内部加载基础 AI 能力、三类工具能力和 `ty` 通用助手。外部页面只通过 `YejiModule` 初始化链路获得 AI 能力。

## 职责边界

通用助手负责唯一 UI 入口、会话状态、输入框、模型调用、流式回复、工具状态和工具路由。

主查询模块负责主查询快照和分页、筛选、字段、模板只读查询。

BI 查询面板模块负责当前面板快照、模板汇总、目标达成、合并模板和动态参数查询。

指标详解模块负责当前指标详解快照、值模型、率模型、预测增强和动态参数查询。

各工具只读，不修改当前页面表格、筛选、分页、模板、目标或弹窗状态。

## 实施阶段

第一阶段，建立文档和契约，明确单入口、多权限、只读工具边界。

第二阶段，新增 `zx/ai/ty` 通用助手模块，复用原聊天布局和流式交互。

第三阶段，停止渲染 BI 查询弹窗和指标详解弹窗内的局部 AI 入口。

第四阶段，删除旧三入口 UI 与适配器文件，只保留快照规则和工具能力。

第五阶段，增强主查询工具，支持模板 key 和模板名称查询。

第六阶段，做语法、乱码、引用和差异审查，确保无旧入口残留。
