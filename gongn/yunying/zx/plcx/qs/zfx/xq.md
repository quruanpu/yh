# 指标详解值模型

适用字段：金额、数量、客户数、边际利润等可以按日期直接累加的指标。

职责：
- 构建每个日期节点的当日数据和累计数据。
- 多模板合并时，对子模板值先累加，再计算当前节点结果。
- 按阶段扩展值模型算法，第一阶段保持线性达成进度，后续阶段逐步加入行业加权节奏、预测和多指标归因。

文件结构：
- `gz.js`：值模型总入口，负责动态加载和聚合阶段算法。
- `yw.js`：值模型业务渲染、行构建和表格入口。
- `jd/jd1.js`：第一阶段，线性达成进度模型。
- `jd/jd2.js`：第二阶段，行业加权节奏模型。
- `jd/jd3.js`：第三阶段总入口，聚合趋势预测、历史曲线校准和剩余压力模型。
- `jd/jd3/gj.js`：第三阶段通用日期、权重和波动工具。
- `jd/jd3/yccl.js`：数据预处理，统一当前和历史的日粒度序列。
- `jd/jd3/jizhunri.js`：数据基准，按节假日、完整周、星期、月内阶段和顺序位置寻找历史对标日期。
- `jd/jd3/tz.js`：特征构建，汇总基准匹配质量、历史曲线波动和参考可靠性特征。
- `jd/jd3/jz.js`：当前周期基准预测模型。
- `jd/jd3/lishi.js`：历史趋势形状参考模型。
- `jd/jd3/yuce.js`：动态融合、预测区间和压力模型。
- `jd/jd4.js`：第四阶段，经营诊断和行动建议模型。
- 后续阶段可在 `jd` 目录新增，例如 `jd5.js`、`jd6.js`，并在 `gz.js` 的阶段配置中注册。

表格列：
- 星期
- 日期

第一阶段，线性达成进度：
- 时间进度
- 值名称目标
- 当日值名称
- 累计值名称
- 值名称达成率
- 进度差
- 进度倍率
- 当日完成强度

第二阶段，行业加权节奏：
- 行业进度
- 权重说明
- 行业预期累计值名称
- 行业节奏差
- 行业节奏倍率
- 目标缺口
- 剩余加权日均

第三阶段，趋势预测和剩余压力：
- 趋势加权日均
- 预测月底值名称
- 预测区间
- 预测达成率
- 预测目标差
- 压力指数
- 预测判断

第四阶段，经营诊断和行动建议：
- 诊断分
- 综合等级
- 关键原因
- 建议动作
- 判断置信度

核心公式：

第一阶段，线性达成进度：
- 达成率 = 累计数据 / 目标
- 进度差 = 达成率 - 时间进度
- 进度倍率 = 达成率 / 时间进度
- 当日完成强度 = 达成率变化 / 时间进度变化

第二阶段，行业加权节奏：
- 行业日权重 = 周内权重 * 月内阶段系数 * 月初延后系数 * 淡旺季系数 * 节假日系数 * 活动系数 * 外部修正系数
- 行业进度 = 查询开始日至当前节点累计行业权重 / 查询开始日至周期结束累计行业权重
- 权重说明 = 当前日期权重来源的自然语言标签，例如周一促销高峰、周三连锁小高峰、周日低谷、月初加权、淡季保守、活动修正
- 行业预期累计 = 目标 * 行业进度
- 行业节奏差 = 累计数据 - 行业预期累计
- 行业节奏倍率 = 累计数据 / 行业预期累计
- 目标缺口 = 目标 - 累计数据
- 剩余加权日均 = 目标缺口 / 剩余行业权重

第三阶段，趋势预测和剩余压力：
- 数据查询与获取：首屏只查当前周期；当前结果渲染后，后台补查上月环期、去年同期、上上月同期，且只改变日期范围，其它模板、字段、筛选和模型口径保持一致
- 数据预处理：把当前和历史数据统一成日粒度序列，补充星期、完整周序号、月内阶段、行业权重、节假日修正、活动修正、累计值和当日值
- 数据基准：先为当前每个日期寻找历史对标日期。节假日优先对节假日，活动修正优先对活动修正，完整周和星期优先匹配，剩余普通日期再按月内阶段和顺序位置匹配
- 基准加权日均 = 目标 / 全周期行业权重
- 累计加权日均 = 累计数据 / 已过行业权重
- 近三日加权日均 = 近三日当日数据合计 / 近三日行业权重合计
- 趋势加权日均 = 基准加权日均、累计加权日均与近三日加权日均的稳健融合。早期样本不足时基准权重更高，中后期样本稳定时累计和近期权重更高
- 历史趋势参考期 = 上月环期、去年同期、上上月同期。后台补查同口径完整周期，不阻塞弹窗首屏
- 历史完成曲线比例 = 当前日期对应的历史基准日期累计数据 / 历史参考期完整周期累计数据。若基准匹配质量不足，再退回行业进度近邻
- 历史趋势预测 = 当前累计数据 / 历史完成曲线比例
- 历史参考权重 = 基础权重 * 可靠性分。基础权重为上月环期最高、去年同期其次、上上月同期最低；可靠性根据数据完整性、基准日期匹配分、节假日错位、曲线波动和异常日集中度修正
- 预测月底累计 = 当前基础预测与历史趋势预测的动态融合。月初历史趋势权重较高，月末当前趋势权重较高
- 预测区间 = 根据行业进度、近三日有效样本、近期波动、历史参考置信度和当前预测与历史趋势分歧生成保守预测与乐观预测
- 预测达成率 = 预测月底累计 / 目标
- 预测目标差 = 预测月底累计 - 目标
- 压力指数 = 剩余加权日均 / 趋势加权日均
- 预测判断根据当前是否已达标、预测目标差和压力指数综合输出

第四阶段，经营诊断和行动建议：
- 诊断分 = 行业节奏分 + 预测结果分 + 剩余压力分 + 近期动能分 + 置信度分
- 综合等级根据诊断分和是否已完成输出。
- 关键原因从目标完成、预测区间、行业节奏、剩余压力、线性进度和近期动能候选原因中按影响权重排序，取最关键原因。
- 建议动作根据综合等级和后续高权重日输出，优先提示周一高峰和周三小高峰承接。
- 判断置信度根据有效样本天数、行业进度和预测不确定性输出，早期样本不足或预测区间过宽时降低置信度。

第二阶段权重口径：
- 星期一权重最高，代表周促峰值。
- 星期三权重次高，代表连锁小高峰。
- 星期日权重最低，避免把周低谷误判为异常。
- 第1周权重较高，第2周回落，第3周小幅修复，第4周及月底回落。
- 当月1日落在周六或周日时，月初加持会延后到后续星期一。
- 7月、8月按淡季保守处理，9月到次年1月按旺季逐步加权处理。
- 节假日系数、活动系数和外部修正系数预留接口。没有传入真实日历或活动数据时默认等于1，避免编造外部事件。

第二到第四阶段合理性：
- 第二阶段解决线性进度误判问题。医药行业存在月初、周一、周三高峰和周末低谷，单看自然日进度容易把正常低谷误判为异常，也容易低估高权重日应承担的目标。
- 第三阶段解决结果预估问题。首屏先使用当前周期数据即时预测，再后台补查历史相似趋势形状做校准。历史参考只校准趋势曲线，不直接平均历史销售值，避免规模变化导致误判。
- 第四阶段解决经营落地问题。业务人员最终需要知道风险等级、主要原因和下一步动作，因此第四阶段不继续堆公式，而是把前面阶段的指标收束成可执行判断。

进一步优化点：
- 第二阶段可在后续接入真实节假日日历和平台活动日权重，当前版本已预留接口但不主动编造活动。
- 第三阶段可在后续接入真实节假日和活动标签，进一步修正历史参考可靠性；也可把历史参考期扩展为近三月相似星期，但默认不增加过多后台查询。
- 第四阶段可在后续加入不同指标类型的动作模板，例如销售额、订单量、客户数、边际利润分别给不同建议。

边界：
- 不负责日期节点生成、请求调度和弹窗壳。
- 不处理率字段的方向判断和分子分母口径，率字段后续由 `lfx` 独立负责。
- 不在 `index.html` 中逐个加载阶段文件，阶段脚本由 `gz.js` 按需动态加载，便于后续增删。
- 第三阶段首屏只做基于当前面板已查询数据的趋势外推；后台增强只补查同口径历史完整周期，查询结果用于趋势形状校准，不改变当前面板事实数据，也不替代人工活动、节假日和供给变化判断。
- 第四阶段只输出规则化经营诊断，不作为硬性业务结论；样本不足、活动信息缺失或节假日未纳入时，应结合人工背景判断。
