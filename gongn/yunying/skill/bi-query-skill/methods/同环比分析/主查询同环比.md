# 主查询同环比

主查询同环比用于客户、商品、品种、区域、活动、单据、明细、贡献结构和采购结构变化分析。工具名为 `yeji_main_query_page`。

## 主体识别

用户只给裸名称且未明确主体时，先识别模板候选，再识别客户、商品或品种候选。

优先级：

1. 名称命中 `availableTemplates.name` 或 `activeTemplateName` 时，按模板路线处理，传 `templateKey` 或 `templateName`。
2. 名称看起来像人员姓名，也不能排除模板。模板常以人员、区域、项目或经营主题命名。
3. 模板索引未加载或快照没有模板列表时，先用只读查询能力验证模板候选。工具返回未找到模板后，再要求用户确认是模板、客户还是品种。
4. 用户明确说客户、药店、客户编码、药店id 时，按客户路线处理。
5. 用户明确说商品、品种、商品编码、spuid、乐药编码、通用名时，按品种路线处理。
6. 同名同时强命中多个主体且会影响查询口径时，只问一个最小澄清问题。

例：用户问“分析刘蕊成同环比”，模板列表存在“刘蕊成”时，必须走模板路线，不能先当客户名称。

## 查询策略

同一层级的本期、同期、环期放入同一个 `queries` 并发查询；每组子查询写明自己的日期、模板或筛选、查询字段、聚合字段、排序和分页。

模板路线：

- 使用命中的 `templateKey`，没有 key 时使用 `templateName`。
- 其它模板筛选和配置保持模板自身口径。
- 第一层查客户贡献：`rowFields:["客户名称"]`，`metricFields:["含税金额"]`，按 `含税金额 desc`，`pageSize:100`。
- 需要商品结构时，再把关键客户去重后传入 `客户名称` 筛选，查 `客户名称 + 商品名称 + 商品规格` 和 `含税金额`。

客户路线：

- 筛选字段按用户原文选择：`客户名称`、`药店id` 或 `客户编码`。不要把药店 id 猜成客户编码。
- 查询客户商品采购：日期字段、`商品名称`、`商品规格`；聚合 `含税金额`、`不含税边际利润`；按 `含税金额 desc`，`pageSize:100`。

品种路线：

- 商品编码用 `ERP商品编码`，spuid 用 `spuid`，乐药编码用 `乐药编码`。
- 用户说“品种名称”但系统没有该筛选字段时，不要创造字段；优先询问是否按 `商品名称`、`ERP商品编码`、`spuid` 或 `乐药编码` 查询。
- 查询品种客户采购：日期字段、`客户名称`、`客户类型`；聚合 `含税金额`、`不含税边际利润`；按 `含税金额 desc`，`pageSize:100`。

若工具返回 `hasMoreData:true` 且未继续分页，结论只能说“已查询页/当前口径范围内”，不能说全量最大。

## 对齐规则

- 同比以同期实体列表为基准，与本期匹配。
- 环比以环期实体列表为基准，与本期匹配。
- 客户优先按 `客户名称` 对齐；商品按 `商品名称 + 商品规格` 对齐。
- 本期存在但基准期不存在，可说明新增或恢复采购；不要混入“以基准期为基准”的掉量榜，除非用户明确要求看新增。

## 禁止事项

- 不要只查本期就回答同环比。
- 不要把同期或环期失败、空数据、未命中当成 0。
- 不要混用不同模板、日期字段或筛选口径计算变化。
- 不要把分页第一页结论说成全量，除非 summary、totalCount 或后续分页支持。
