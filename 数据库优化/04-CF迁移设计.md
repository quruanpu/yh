# 04 · CF 迁移设计（Workers + D1，最终实施方案）

> 状态：设计完成，等用户"动手"指令后执行。
> 用户已确认：CF 账号已有（wrangler login 授权）；轮询间隔 10 秒；鉴权档位待拍板（建议 Origin 白名单 + 令牌双层）。
> 硬约束：前端部署不变（GitHub Pages + 自定义域名）；免费；sjk 驱动内改，16 个业务域文件零改动。

## 1. 架构

```
浏览器（GitHub Pages + 自定义域名，不变）
    │ fetch + Origin 自动携带 + x-yh-token 头（前端内嵌，无感）
    ▼
CF Worker yh-data-gateway（*.workers.dev 或未来 api 子域）
    ├─ Origin 白名单校验（用户自定义域名 / localhost / tcloudbaseapp 静态托管域名）
    ├─ 令牌校验（x-yh-token，env secret，可开关）
    ├─ 12 个 op（get/getWhere/getAll/add/set/update/upsert/remove）+ 集合白名单
    ├─ 空库容错（集合/文档不存在 → null/[]，与 SjkModule 前端约定同构）
    ▼
D1 数据库 yh-data
    └─ 单表 docs(collection TEXT, id TEXT, data TEXT(JSON), updated_at INTEGER)
       PRIMARY KEY (collection, id)
```

## 2. Worker API 规格

POST 单一入口，body：
```json
{ "op": "get|getWhere|getAll|add|set|update|upsert|remove",
  "collection": "...", "docId": "...",
  "data": {}, "patch": {},
  "field": "...", "value": null, "limit": 200 }
```
- 校验顺序：Origin 白名单 → 令牌 → op 合法性 → 集合白名单 → 执行。
- 查询：`WHERE collection=? AND json_extract(data, ?) = ?`（路径 `$.field` 作为绑定参数，防注入；仅支持 `==`，与现有全部用例一致）。
- 抢占（优惠券任务）：`UPDATE docs SET data=? WHERE collection=? AND id=? AND json_extract(data,'$.tasks.<taskId>.status')='pending'` → `meta.changes` 判定（原子，等价原事务）。
- update 严格语义 / upsert：Worker 端 SELECT 存在性后分支。
- 响应：`{ ok: true, data }` / `{ ok: false, error }`；OPTIONS 204。
- 集合白名单：login_accounts、device_logins、yeji_templates、yeji_targets、coupons、coupon_index、notebooks、gongju_items、model_configs。
- 静态资源：GET 返回简单健康信息（或 404）。

## 3. SjkModule 驱动改造（sjk/app.js 内部）

- `config.gatewayUrl`（workers.dev 地址）、`config.token`（前端内嵌令牌）、`config.pollMs = 10000`。
- `init()`：改为轻量健康检查（GET worker，失败不阻断、标记 degraded）。
- 12 个 API 签名不变；内部 `this._call(op, params)` → `fetch(gatewayUrl, POST)` + 10s 超时 + `{ok,data}` 解包 + 错误归一。
- `watchWhere/watchCollection`：轮询实现——立即首跑一次 → `setInterval(10000)` → `document.hidden` 时暂停、恢复时立即补跑 → 返回 unwatch（clearInterval）。回调参数保持 `{ docs, type: 'poll' }`。
- 移除 CloudBase SDK 依赖（index.html 删 CDN 引用）。
- 旧 CloudBase 驱动实现存于 git 历史（84e10a9 及后续提交），回滚 = git revert + 恢复 CDN 行。

## 4. 鉴权设计（用户已拍板：Origin 白名单 + 令牌双层）

**Origin 白名单规则**（Worker 内实现，解析 Origin 的 hostname 做后缀精确匹配，防钓鱼仿冒）：

| 来源 | 匹配规则 |
|---|---|
| `ly.cqytyy.top` | 精确匹配（前端正式域名） |
| `cqytyy.top` 及任意子域 | 后缀匹配（用户要求：cqytyy 域名下子域均可访问） |
| `localhost` / `127.0.0.1` | 精确匹配（本地开发 http/https 均可） |
| **腾讯云来源（tcloudbaseapp.com 等）** | **不加入白名单**（用户决定彻底排除腾讯云链路） |
| **缺失/不匹配 Origin** | 403 拒绝（挡陌生脚本直连） |

**令牌设计**：
- 部署时生成一次随机令牌（40 位），写入 Worker secret `YH_TOKEN` + 前端 `sjk/app.js config.token`；
- 前端所有请求自动携带 `x-yh-token` 头（使用者零感知、零输入）；
- **无有效期、无需定期轮换**；仅在怀疑泄露时主动轮换（改 Worker secret + 前端常量 + 重新发布，约 10 分钟）；
- Worker 校验失败返回 401。

**双层对使用者的体验**：完全无感（浏览器自动带 Origin，前端自动带令牌）。

## 5. 部署流程（动手时执行）

1. `npm i -g wrangler`（npmmirror 源）
2. `wrangler login`（调起浏览器，用户登录点 Allow）
3. `wrangler d1 create yh-data` → 记录 database_id → 写入 wrangler.toml
4. `wrangler d1 execute yh-data --file schema.sql`（建 docs 表）
5. `wrangler secret put YH_TOKEN`（随机 40 位，同时写入前端 config）
6. `wrangler deploy` → 获得 workers.dev URL
7. curl 六步读写测试（模拟 Origin 头）+ **用户浏览器实测可达性**
8. 可达性不通 → DNS 迁 CF 绑 api 子域（第二步预案）
9. sjk 驱动切换 → node --check + 行为回归（harness 改 HTTP mock 或直接真实 Worker 测）
10. 部署：GitHub push（用户自定义域名）+ CloudBase 静态托管同步（回退通道）
