# 07 · DO 实时推送实施设计（写时广播 + 即时拉取 + 分层兜底）

> 基线：Worker 10 op（6 写 op）已部署十项全绿；SjkModule 12 API + 10s 轮询已就位。
> 本设计只新增"实时层"：读写查询 API / 业务域 / UI 全部不动。
> 验证纪律：所有文件改动后经 PowerShell 回读/码点抽查 + node --check；测试输出落盘后完整读取。

## 1. 最终架构

```
写路径（现有 6 写 op，各 +1 行通知）：
  Worker 写 D1 成功 → notifyCollection(env, col) → DO /notify（内部调用，失败忽略）
  → YhNotifyDO 广播 {collection} 给所有订阅该集合的 WebSocket（Hibernation）

前端订阅层（SjkModule 内部，替代 _startPolling 为默认路径）：
  watchWhere/watchCollection → 注册订阅 {fetcher, callback}
    ├─ WebSocket（1 条长连接/页面，休眠挂机零消耗）
    │    连接 → 首消息认证 {token, collections:[]} → 收 {collection} → 立即 fetcher() → callback({docs, type:'push'})
    ├─ 60s 兜底轮询（防通知丢失；推送正常时数据不变则不触发 UI）
    └─ 降级链：WS 连接失败/关闭 ≥2 次 → degraded 轮询 10s + 每 30s 重试 WS；WS open → 恢复 60s + 立即补拉
DO 侧自检（兜住"通知失败"漏洞）：
  alarm 每 60s 查 D1 各集合 MAX(updated_at) → 与 storage 版本比对 → 变化即广播
```

## 2. Worker 改动点（sjk/worker/）

| 位置 | 改动 |
|---|---|
| 新增 `export class YhNotifyDO` | fetch：/connect（WS 升级，query token + Origin 校验，tags=collections）、/notify（POST {collection}，广播 getWebSockets(tag)）；webSocketMessage：订阅变更（state.setTags）；webSocketClose：自动清理（hibernation 内建） |
| 新增 `async alarm()` | DO storage 版本表 vs D1 `SELECT collection, MAX(updated_at) FROM docs GROUP BY collection` → 变化集合广播 + storage 更新；重设 alarm(+60s) |
| 6 个写 op 成功后 | `await notifyCollection(env, col)`（try/catch 忽略失败） |
| fetch 路由 | /connect、/notify 路径分发到 DO stub（idFromName('global')）；其余走现有 handle |
| wrangler.toml | `[[durable_objects.bindings]] name="YH_NOTIFY" class_name="YhNotifyDO"` + `[[migrations]] tag="v1" new_sqlite_classes=["YhNotifyDO"]` |
| 鉴权 | WS 升级：Origin 白名单 + query token == env.YH_TOKEN；/notify：仅内部（Worker→DO binding 调用自带可信性，仍校验内部标记） |

注意：WS 浏览器构造器不能自定义 header → 令牌走 query 参数 `?token=...`（或首消息认证，二选一，采用 query 简单方案）。

## 3. 前端订阅层规格（sjk/app.js）

```
state 新增: ws, wsAttempts, degraded, subs(Map key=`${collection}|${field}|${value}` 或 `${collection}|*`), pollTimer
watchWhere(collection, field, value, callback):
  key = collection+'|'+field+'|'+JSON.stringify(value)
  subs.set(key, {collection, fetcher:()=>getWhere(col,field,'==',value), callback})
  ensureRealtime(); return () => { subs.delete(key); if(!subs.size) closeRealtime(); }
watchCollection(collection, callback):
  key = collection+'|*'
  subs.set(key, {collection, fetcher:()=>getAll(col), callback})
  ensureRealtime(); return () => {...}
ensureRealtime():
  若 ws 已连/连接中 → return
  new WebSocket(config.wsUrl + '?token=' + token)   // wsUrl: 生产 '/api/sjk-ws'(同源经 Vercel) 本地 'ws://localhost:8787'
  onopen: wsAttempts=0; degraded=false; pollTimer 切 60s; 立即补拉全部 subs
  onmessage: {collection} → 遍历 subs 中 collection 匹配者 → fetcher() → callback({docs, type:'push'})
  onclose/onerror: attempts++; 若 subs.size>0 → degraded=true → 轮询 10s；30s 后重试连接
  令牌失效(服务端 close code 4001) → 停止重试，保持 degraded 轮询
_config.wsUrl: (localStorage.getItem('sjk_ws')) || '/api/sjk-ws'
```
- 回调 `{docs, type:'push'|'poll'}` 签名不变 → 业务域零改动；
- 轮询与推送共存：推送触发后 60s 轮询照常跑（数据未变时前端 lastJson 去重，不重复回调 UI）；
- 上线前的 workers.dev 阶段：wsUrl 覆盖为 `wss://yh-data-gateway.cqytxy001.workers.dev`（localStorage 开关）。
