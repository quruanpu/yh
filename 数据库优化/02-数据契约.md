# 数据库优化 · 数据契约（旧实现为唯一事实源，改造逐条对照）

> 本文档固化各域的读/写/监听行为与字段结构。改造任何文件前先对照这里；改造完成后如有行为差异必须回写修正。

## 1. 账户库（login_accounts，原 zhanghu/{sys}/providers/{pid}/accounts/{acc}）

**文档结构（字段名不变）**：
```
{
  system, account, username(仅scm), credentials, account_secret(仅scm),
  provider_info(仅scm), provider_id, provider_name,
  user_info, permissions(仅pms),
  devices: { [deviceId]: { login_time, device_info } },
  invalid: false, invalid_time, login_time, last_update
}
```

**方法契约（denglu/zhanghu.js 必须对齐）**：
| 方法 | 行为 |
|---|---|
| `saveSystemLogin(system, provider, account, payload)` | 归一化账户 → 写账户文档 + 写设备索引文档（原为一次原子 update，新为两写，顺序：先账户后索引） |
| `saveScmLogin(username, credentials, providerInfo, accountPassword)` | provider 从 credentials/providerInfo 归一；user_info={account, username}；accountPassword→account_secret |
| `savePmsLogin(account, credentials, userInfo, permissions)` | provider 从 credentials/permissions/userInfo 归一；**回填 credentials.providerId/Name**（原行为） |
| `saveBiLogin(account, credentials, userInfo, providerId, providerName)` | 直接落文档 |
| `getScmLogin/getPmsLogin/findBiByAccount(account, providerId)` | 精确取账户文档；无则 null |
| `findAll{Scm,Pms,Bi}ByProviderId(providerId)` | 查询该 provider 全部账户，**过滤** `(credentials \|\| account_secret) && !invalid`，按 login_time 降序 |
| `markAccountInvalid/clearAccountInvalid(system, pid, acc)` | 账户文档 invalid/invalid_time/last_update + 该账户对应**所有设备索引**的 invalid 同步 |
| `unshareLogin(system, pid, acc, mode)` | mode='secret'→清 account_secret；'credentials'→清 credentials；两者皆空→**删账户文档 + 删全部设备索引文档** |
| `getDeviceLogins(systemFilter)` | 查 device_logins 中当前 deviceId 的索引（跳过 invalid）→ 逐个取账户 → 过滤 `(credentials\|\|account_secret) && !invalid` → 按 login_time 降序 → 返回 `{scm:[{...账户, username, provider_name}], pms:[{...账户, provider_id, provider_name, user_name}], bi:[{...账户, user_info}]}` |

## 2. 设备索引（device_logins，原 zhanghu/{sys}/devices/{dev}/{idxKey}）

```
{ system, provider_id, provider_name, account, username, login_time, invalid: false }
```
写入点：saveSystemLogin 内同步写入（device 键 = 当前 DeviceModule.deviceId）。

## 3. BI 模板（yeji_templates，原 moban/yeji/{pid}/{key}）

- `getTpls(pid)` → 查询 pid 字段 → 返回 `[{...tpl, _key: key}]` 按 time 降序（mb.js 侧还有排序，双保险一致）；
- `saveTpl(pid, tpl)` → 生成 key（时间戳+随机），写入 `{ pid, key, ...tpl }`，返回 key；
- `updateTpl(pid, key, tpl)` → 按 `{pidKey}::{key}` 覆盖（保留 pid/key 字段）；
- `deleteTpl(pid, key)` → 删除文档。

## 4. 批量查询目标（yeji_targets，原 moban/yeji_mubiao/{pid}/ultra_v2）

- `getYejiTargets(pid)` → 文档 `{ version: 1, module: 'ultra', ranges: {rangeKey: payload}, updatedAt }`；无则返回默认 `{version:1, module:'ultra', ranges:{}}`；
- `saveYejiTargetRange(pid, rangeKey, payload)` → 读改写 ranges[rangeKey] + updatedAt；
- `deleteYejiTargetRange(pid, rangeKey)` → 读改写删除该键。

## 5. 优惠券（coupons / coupon_index，原 yhq_gx/{pid}/... 与 yhq_gx_index/{pid}）

- 券文档：`{ provider_id, couponId, ...原券字段, tasks: { [taskId]: {...} } }`（tasks 内嵌对齐原树）；
- 列表读取 → 返回 `{ couponId: 券对象 }` 形式（与原 snapshot.val() 同构）；
- **实时监听**（唯一一处，yhquan/app.js）：原 `.on('value')` 推送整个 `{couponId: 券}` → 新 `watch(coupons, provider_id=pid)` 每次变更回调同样的 map 结构；
- `yhq_gx_index/{pid}` → coupon_index 文档 `{ provider_id, ...原字段 }`；删除动作语义保持（无券时移除索引文档）。

## 6. 记事本（notebooks，原 jishiben/{pid}/...）

- 整树内嵌：文档 `{ __meta: { updated_at }, ...原 nodePath 树 }`；
- `__meta/updated_at` 写入 → update `'__meta.updated_at': now`；
- 读取 root → get 文档（无则 null）。
