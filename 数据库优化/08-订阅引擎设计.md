# 08 · 订阅引擎设计（sjk/realtime.js——实时订阅收编到数据层）

> 起因：工具中心订阅依赖 provider 前置条件，未就绪时静默失败且无重试 → 列表僵死。
> 方向（用户定调）：订阅作为数据层标准能力，"谁需要谁直接调用"，业务层不再自管订阅状态机。

## 1. 职责矩阵（改造前/后）

| 职责 | 改造前 | 改造后 |
|---|---|---|
| WS 连接/认证/重连/降级 | sjk/app.js（雏形） | **sjk/realtime.js**（完整状态机） |
| 订阅注册/去重/取消 | sjk/app.js _register | **sjk/realtime.js** |
| 通知→拉取→回调 | sjk/app.js | **sjk/realtime.js** |
| **拉取失败自动重试（自愈）** | ❌ 无（一次失败即僵死） | **✅ 引擎内置退避重试（5s→10s→…上限 60s）** |
| 60s 兜底轮询 | sjk/app.js | **sjk/realtime.js** |
| provider 过滤等业务逻辑 | 业务模块 | 业务模块（回调/拉取时动态取） |
| 业务侧状态机（unsubscribe/providerId） | kuangjia 自管（40 行） | **删除**（引擎管理） |

## 2. SjkRealtime 规格（sjk/realtime.js）

```js
window.SjkRealtime = {
    config: { wsUrl, token, pollMs: 60000, degradedPollMs: 10000, retryBaseMs: 5000, retryMaxMs: 60000 },
    state: { ws, wsState, subs: Map(key -> {collection, fetcher, callback, lastJson, failCount, nextRetryAt}), pollTimer, reconnectTimer, degraded },

    subscribe(key, collection, fetcher, callback) -> unwatch
    // 注册即保证：持续重试直到成功；通知/轮询/重试三路都会触发 fetcher->callback
    unsubscribe(key)
    setCollections(cols)   // WS 订阅清单同步（连接后/变更时）
}
```

**自愈时序（治本点）**：
```
subscribe 注册 → 拉取
  ├─ 成功 → callback（UI 出数据）
  └─ 抛错（如 provider 未就绪）→ failCount++ → 退避重试（min(5s*2^n, 60s)）
       └─ 每次重试成功 → failCount=0 → callback（UI 自愈）——无需任何人干预
```
- 重试由**统一调度器**驱动（每 tick 检查各 sub 的 nextRetryAt，到点即拉）——不额外开定时器；
- 通知（WS）触发的拉取不受 failCount 限制（每次通知都尝试，成功即自愈提前）。

## 4. 调用方改造（仅工具中心）

**kuangjia/yewu.js（改造前 ~40 行状态机）→（改造后）**：
```js
async ensureSubscribed() {
    if (this.state.unsubscribe) return;
    this.setLoading();
    this.state.unsubscribe = await GongjuzxGongju.subscribeItems(
        (list) => { this.state.allItems = Array.isArray(list) ? list : []; this.renderList(); },
        (err) => { console.error('[工具中心] 订阅失败', err); this.showToast(err?.message || '加载失败', 'error'); }
    );
}
```
**gongju.js subscribeItems（改造后）**：provider 过滤移到每次拉取时动态执行；未就绪抛错（交由引擎重试）：
```js
async subscribeItems(onChange, onError) {
    await this.ensureDatabase();
    const pull = async () => {
        const provider = await this.getProviderInfo();          // 每次拉取动态取
        const docs = await window.SjkModule.getAll('gongju_items');
        if (!provider.provider_id) { onChange([]); return; }     // 未就绪：空列表，引擎会持续重试
        onChange(this.normalizeList(this._docsToRawMap(docs), provider.provider_id));
    };
    const unwatch = window.SjkRealtime.subscribe('gongju_items|*', 'gongju_items', pull, ({ }) => {});
    return () => unwatch();
}
```
（实现细节：subscribe 的 callback 作为通知触发器，pull 内部自行调 onChange——外部签名不变。）

**其他调用方（yhquan×2）**：零改动，自动获得失败自愈。

## 5. 兼容与收口

- `SjkModule.watchWhere/watchCollection` 签名不变（内部委托 SjkRealtime.subscribe）；
- 数据库层收口不变：sjk/（app.js 数据 API + realtime.js 订阅引擎）+ sjk/worker/（Worker+DO）；
- 业务域 16 文件零改动（仅 kuangjia/gongju 净减代码）；
- app.js 中原 _startPolling/_ensureRealtime/_handleWsFailure 全部迁出（app.js 只剩数据 API，更纯粹）。

## 6. 测试计划

1. 单元（harness）：fetcher 前 2 次抛错第 3 次成功 → 断言重试后回调触发（自愈）；
2. 回归：现有 18 断言全绿（API 语义不变）；
3. 本地 wrangler dev：工具中心 打开→添加→删除 全程 UI 即时刷新（复现用户场景闭环）；
4. 部署后：双窗口 <1s 同步（推送）。

## 7. 验收标准

- 工具中心：刷新页面 → 打开即出数据（或数秒内自愈出现）——**不再僵死**；
- 添加/删除 → 本端与其他端均即时刷新；
- 代码净变化：kuangjia/gongju 减行、realtime.js 增行、总行数基本持平；层级：业务/订阅引擎/数据 API/Worker 四层清晰。
